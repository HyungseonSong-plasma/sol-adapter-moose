# A0.1 Phase 0 — Rust Host & Contract Boundary

**Issue:** #3  
**Status:** implementation candidate

## Boundary

Phase 0 establishes only the external Rust adapter host and the published SOL 0.1 contract/transport boundary.

```text
SOL caller
  <-> JSON-RPC 2.0 / LF-delimited stdio
sol-adaptor-moose
  -> Adapter Protocol 0.1 DTO behavior
  -> Public Contract 0.1 reused DTO behavior
```

No MOOSE executable, object registry, thermal translation, input generation, or solver side effect is part of this Phase.

## Contract source consumption

The repository vendors an exact source snapshot from `HyungseonSong-plasma/simulation-ontology` commit `69779d3ab7880f56618b29af82616965776e0126` because the current external-project examples do not provide a stable independently published Rust package boundary and cross-private-repository Git dependencies would introduce CI authentication coupling.

The snapshot is implementation provenance, not semantic authority. `VENDORED_SOL_SOURCE.md` records the source and replacement rule. Public Contract 0.1 and Adapter Protocol 0.1 remain the normative interoperability authority.

## Phase-0 adapter state

The adapter declares:

```text
adapter_id = sol.adapter.moose
adapter implementation version = Cargo package version
supported Adapter Protocol = 0.1
supported Public Contract = 0.1
targets = []
```

The empty target set is intentional. The repository has not yet established exact executable/package evidence for a MOOSE target; that is Phase 1 #4. Preflight and execution therefore reject backend requests without creating side effects or assigning physics meaning to MappingPlan action IDs.

## Stream discipline

- stdout is reserved for JSON-RPC protocol frames;
- fatal host/transport diagnostics use stderr;
- ProtocolFailure remains a normal Protocol result payload;
- malformed JSON-RPC/envelope input remains a transport error response.

## CI bootstrap

The Rust workflow entry point was bootstrapped on `main` by PR #10, merge `946ed918a2cc20fb07a4c61398cdeed3119e7a54`. On revisions without `Cargo.toml`, it explicitly skips Rust build/test steps; on this Phase 0 branch it must execute dependency-lock generation, formatting, tests, and Clippy.

## Verification claim

Phase 0 may establish Rust host/transport behavior and exact SOL 0.1 source provenance. It does **not** establish:

- a supported MOOSE target;
- thermal realization correctness;
- MOOSE integration;
- numerical V&V;
- resolution of upstream `simulation-ontology#110`.
