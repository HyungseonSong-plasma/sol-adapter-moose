# A0.1 Foundation — Backend-only Execution Workspace

**Scope:** meaning-neutral backend foundation while Public Contract 0.2 / Adapter Protocol 0.2 `RealizationSpec` remains outstanding.

## Purpose

Connect the already-established deterministic MOOSE IR and workspace layout into an adapter-local backend execution boundary without assigning any SOL semantic meaning to the generated model.

The backend-only path is:

```text
adapter-local MOOSE IR
        -> deterministic .i text
        -> deterministic workspace input.i
        -> exact-tested MOOSE child process
        -> captured stdout/stderr
        -> deterministic stdout.log / stderr.log artifacts
```

This is backend execution evidence only. It is not `execute_plan`, not canonical SOL realization, and not a thermal compatibility claim.

## Required properties

- execution occurs inside the validated deterministic run directory;
- the generated input is written as `input.i` before launch;
- child stdout and stderr remain isolated from adapter JSON-RPC stdout;
- captured streams are persisted as `stdout.log` and `stderr.log` even when the backend exits unsuccessfully or times out after launch;
- existing timeout and child-termination behavior remains intact;
- the existing exact MOOSE evidence target is unchanged;
- no `MappingPlan` action ID or other 0.1 field is interpreted as physics.

## Evidence boundary

Allowed evidence:
- adapter-local workspace determinism;
- backend process working-directory isolation;
- backend-only `.i` execution against the exact tested MOOSE executable;
- artifact capture behavior.

Not established:
- SOL thermal semantics;
- Public Contract / Adapter Protocol 0.2 support;
- canonical thermal mapping;
- Protocol `execute_plan` realization;
- numerical V&V;
- broad MOOSE version compatibility.
